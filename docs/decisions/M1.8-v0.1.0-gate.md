## 5. Capability Definition

The following definition was derived directly from `engine.ts`. Every verb corresponds to an implemented function. No verb exceeds the current implementation.

> **Decision Intelligence** is Aryntra's deterministic decision-analysis capability. It evaluates named alternatives against weighted constraints, scores each option, surfaces explicit trade-offs between the top candidates, flags uncertainty, calculates confidence, and produces a human-readable reasoning trace. It does not use AI models. It does not make decisions. It makes the reasoning behind decisions visible before commitment.

## 6. Public Claims

### 6.1 Approved Claims

These may appear on the public page, in meta descriptions, and in headings:

```
 1. Decision Intelligence is implemented as a working prototype.
 2. It evaluates alternatives against weighted constraints.
 3. It produces ranked options with percentage scores.
 4. It identifies explicit trade-offs between top alternatives.
 5. It calculates confidence levels (High / Medium / Low).
 6. It surfaces uncertain constraints (partial satisfaction).
 7. It produces transparent reasoning traces.
 8. The reasoning engine is deterministic — same input, same output.
 9. No AI model is used. No external API is called.
10. It has been demonstrated across two different decision domains:
    infrastructure architecture and personnel hiring.
11. The same core engine processed both domains without modification.
12. Input is provided via structured JSON.
```

### 6.2 Conditional Claims

These may appear only with explicit qualification:

```
- "Constraint evaluation engine" — clarify it is deterministic, not AI-based.
- "Decision support" — clarify the system recommends, not decides.

  satisfaction levels, not learned from data.
```

None of these are currently true. The M1.6 contract explicitly forbade them, and M1.8 reaffirms that prohibition.

### 9.2 The Problem

```
Purpose:    Why this exists
Content:    Teams make high-stakes decisions without making trade-offs
            explicit. The reasoning happens in heads, not in shared,
            reviewable form. By the time a decision is committed, the
```

```
Purpose:    Explain the mechanism without overselling
Content:    The six-step pipeline:
              1. Define alternatives
              2. Define constraints with weights (1–5)
              3. Assign satisfaction levels (Pass / Partial / Fail)
              4. Calculate weighted scores
              5. Surface trade-offs between top options
              6. Generate recommendation with reasoning trace
            Emphasise: deterministic, no AI, transparent.
```
