## 3. What was built

### Architecture
- Established `pnpm-workspace.yaml` at repository root (was missing)
- Removed the erroneous `pnpm-workspace.yaml` inside `apps/web`
- Established root and app-level `.gitignore` rules
- Directory structure created per §17 of the sprint brief

### Design system
- `app/globals.css` — semantic design tokens, Tailwind v4 `@theme inline` mapping
- Dark surface palette (`#09090b` background, layered surfaces, muted greys)
- Aryntra accent (`#6366f1` — indigo) with dim and glow variants
- Global focus-visible outline
- `prefers-reduced-motion` handling
- Custom text selection color

### UI primitives (`components/ui/`)
- `Container` — max-width wrapper with responsive horizontal padding
- `Button` — polymorphic `a` / `button`, `primary` / `ghost` variants, `sm` / `md` sizes

### Layout (`components/layout/`)
- `Navbar` — fixed, backdrop-blurred, wordmark + `PHASE 0` tag
- `Footer` — identity block, single real nav link, copyright

### Sections (`components/sections/`)
- `Hero` — full-viewport, subtle grid + radial accent glow, headline, tagline, dual CTAs, scroll indicator
- `Introduction` — two-column layout with philosophy headline and body
- `DecisionLayer` — numbered vertical pipeline visualisation
- `Exploration` — three-column responsive card grid (6 exploration areas)
- `Future` — centered narrative + ASCII banyan-tree hint

### Content layer (`content/company/`)
- `positioning.ts` — name, tagline, descriptions, year
- `philosophy.ts` — headline, body paragraphs, decision pipeline
- `exploration.ts` — six exploration area definitions with typed union

Content is source-controlled TypeScript. UI components consume it via `import`
— the boundary allows swapping to MDX, CMS, or API later without rewriting
presentation.

### Metadata (`app/layout.tsx`)
- Title, description, Open Graph, Twitter Card, robots directives
- `metadataBase` set to `https://aryntra.com`
- Geist Sans + Geist Mono loaded via `next/font/google` with `display: swap`

## 8. Architectural decisions worth remembering

1. **Content lives in TypeScript, not JSX** — enables migration to MDX/CMS/API
   later without rewriting components. Stable contract, replaceable implementation.
2. **Semantic tokens, not hard-coded colors** — visual identity can evolve
   without touching component internals.
3. **Section components own their layout, not `page.tsx`** — the page is a
   composition, not a monolith.
4. **`packages/*` deliberately empty** — no premature package extraction. A
   package earns its existence when there's genuine cross-application reuse.
5. **No ecosystem infrastructure** — future branches will grow when they earn
   a branch. Phase 0 is the trunk.
