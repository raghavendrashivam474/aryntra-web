# M1.7 — Scenario B

**Milestone:** M1.7
**Date:** 2025-08-19
**Status:** Validated
**Purpose:** Define a meaningfully different decision scenario to test generalisation.

---

## Decision

Hire a senior backend engineer for a 12-person Series A startup that must ship a core API rewrite within 2 months, with a base salary cap of $160k.

## Context

- Company stage: Series A, 12 employees, 5 engineers
- Tech stack: Go, PostgreSQL, Kubernetes
- Urgency: API rewrite must begin within 2 months
- Budget: $160k base salary cap (runway constraints)
- Remote policy: Hybrid, 3 days in office

## Alternatives

1. **Candidate A — Senior Go Engineer at Stripe (7 YOE):** Deep technical expertise and fintech domain knowledge, but over budget ($185k+ expected) and uncertain on start date and cultural fit.
2. **Candidate B — Backend Lead at Series B Startup (5 YOE):** Strong technical skills, proven leadership, within budget ($155k), available in 3 weeks, startup-native. Only gap: no direct fintech experience.
3. **Candidate C — Staff Engineer at Big Tech (10 YOE):** Most experienced, excellent leader, but over budget ($180k+), unavailable for 9 weeks, and culturally mismatched with startup environment.

## Constraints

| Constraint | Weight | Rationale |
|---|---|---|
| Deep Backend Systems Experience (Go/PostgreSQL) | 5 | Core requirement for the API rewrite |
| Can Mentor Junior Engineers | 4 | 3 juniors on team need elevation |
| Base Salary <= $160k | 4 | Series A runway is tight |
| Can Start Within 4 Weeks | 5 | 2-month deadline leaves no room for delay |
| Comfortable With Ambiguity | 3 | Startup environment, shifting requirements |
| Fintech/Payments Domain Experience | 2 | Nice to have, reduces ramp-up |

## Evidence

- Candidate A: Stripe payments team, $195k current comp, 4-week notice
- Candidate B: Led API rewrite at 20-person startup, $135k current, 2-week notice
- Candidate C: Staff-level at Big Tech, $320k total comp, 9-week availability

## Expected Decision Factors

The engine should identify that Candidate B's consistency across all high-weight constraints outweighs Candidate A's superior domain knowledge (lowest weight) and Candidate C's superior experience (negated by budget and availability failures).

## Success Criteria

- Recommendation should be Candidate B
- Trade-off should name domain knowledge as the sacrifice
- Confidence should be HIGH given the large score gap
- The output should be credible to a hiring manager

## Why This Scenario Is Meaningfully Different

| Dimension | Scenario A (Architecture) | Scenario B (Hiring) |
|---|---|---|
| Domain | Technical infrastructure | People / HR |
| Options | Software architectures | Human candidates |
| Constraint types | Budget, performance, ops | Salary, availability, culture |
| Evaluation basis | System capabilities | Human qualifications |
| Decision maker | Engineering team | Hiring manager |
| Stakes | Technical debt, velocity | Team composition, runway |

The engine processed both scenarios without any modification. The domain difference is entirely in the data.
