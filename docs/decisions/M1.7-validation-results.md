## 2. What Remained Unchanged?

These are the **core Decision Intelligence capability**:

- `engine.ts` — completely unmodified, zero changes
- `evaluate()` function signature and behaviour
- Constraint evaluation logic (PASS=1.0, PARTIAL=0.5, FAIL=0.0)
- Weighted scoring algorithm
- Trade-off analysis (compares top two, names wins and losses)
- Confidence calculation (margin-based: HIGH >= 20%, MEDIUM >= 8%, LOW < 8%)
- Uncertainty flagging (surfaces all PARTIAL constraints)
- Reasoning trace construction

**The entire reasoning engine is domain-agnostic.**

---

## 3. What Had to Change?

- **Input mechanism:** Added `run-json.ts` to read scenarios from JSON files instead of TypeScript imports. The original `run.ts` was not modified.
- **Text wrapping:** `run-json.ts` uses word-boundary-aware wrapping, fixing the M1.4 mid-word-break bug. Original `run.ts` retains old behaviour.
- **Scenario data:** New JSON files with different domain content. No code changes required.

---

## 4. What Broke?

**Nothing.** Both scenarios executed successfully on the first attempt after resolving the UTF-8 BOM encoding issue (PowerShell `Set-Content` writes BOM by default; fixed by using `[System.IO.File]::WriteAllText` with `UTF8Encoding($false)`).

The BOM issue was an infrastructure concern, not an engine limitation.
